# 需求与验收计划

本文定义验收要求，不维护阶段状态，也不宣称所有规格已实现。首版只针对 Android；阶段与证据入口见 current-state。用户需求与产品推导见 user-needs。

| 编号 | 场景 | 必须满足 |
|---|---|---|
| R1 | 任意 Agent 接手 | --help、capabilities 和统一 JSON 足够使用；skill 不是运行依赖 |
| R2 | 自动留存 | 经入口的探索和重放均自动写动作前后事件；关闭会话/进程后仍可查询 |
| R3 | 跨 Agent | 两个实际不同 Agent，引擎独立、无原聊天，B 能 discover、绑定新参数并 run A 所学 |
| R4 | 候选隔离 | 未达晋级条件只能参考或 validate，普通 run 拒绝；伪造 summary success 无效 |
| R5 | 匹配 | 多个候选、不同设备/App/版本/账号上下文和缺参数不误选；返回具体原因 |
| R6 | 熟路速度 | 一次调用完成，中途 Agent 规划/修正次数为零；程序检查不算模型思考 |
| R7 | 业务成功 | 必需后置条件全部通过；错误实体、工具无报错、只到达页面不能伪报 completed |
| R8 | 状态新鲜度 | 旧观察、页面改变、旋转和外部干扰不能被当作有效定位证据 |
| R9 | Jev 边界 | 确定性可判定时不调用；未知/超时暂停；缺服务不阻塞纯结构任务 |
| R10 | 现场交接与恢复 | 返回当前阶段/页面、目标身份、已完成/未知步骤、未满足条件、观察时效/证据、租约/在途动作状态及待判断问题；默认不重启或整段重来；刷新现场并验证恢复点，不确定动作不盲重试；无可信恢复点明确 needs_replan |
| R11 | 版本修复 | 旧版本保留，修复新建候选，重新验证；环境变化不污染其他环境历史 |
| R12 | 并发与崩溃 | 同设备双运行被拒绝；日志/版本不被覆盖；半写事件不造成误报完成 |
| R13 | 数据边界 | 密钥及敏感输入不落盘；运行数据不入源码；外部写授权不跨任务继承 |
| R14 | 结果可用 | 声明的字段在 data.outputs 返回；查询 ok/0，探索 recorded，只有冻结的任务后置条件通过才 completed |
| R15 | 真实接手 | 新 Agent 从安装说明/帮助发现同一存储；暂停租约释放，活跃会话不被抢占，未知子进程未结束不允许新写 |
| R16 | 去重与恢复 | 同 request_id 不重复动作；逻辑失效不可 resume 绕过验证；失败只影响相应环境状态 |
| R17 | 经验持久性 | 未 propose 的运行摘要长期可检索；catalog 重建不丢资格/错误赋权；配方摘要变化使旧验证无效 |
| R18 | 范围控制 | 首版不实现图搜索、通用分支语言、定时清理、纯视觉成功自动晋级或外部写操作自动重放 |
| R19 | 强引用执行记录 | 关键结论能通过run/事件序号/内容摘要回查实际观察、动作、成本和结果；缺失/清理/改动可辨认，不用聊天记忆补造事实 |
| R20 | 复盘与改进 | 项目skill按完成证据、成本、重复、原因/假设、适用边界、下一实验六问形成有依据复盘；失败/无改进如实保存，最小改动须对照验证 |
| R21 | 经验消费 | 新独立Agent无需原聊天即可查询有来源的经验并用于执行或改进；经验文本不能自动授予Journey资格，反证保留，不跨项目混存 |

R19–R21 来自2026-10-23用户接受的日志/反思方向；先在本项目完成再推广全局skill，实施依赖见 implementation-plan T0–T8。原A–D门槛不降低；新增闭环需单独提供至少一次实际任务到复盘、经验消费、验证改进的完整证据。

## 测试层次

先以固定观察样本与假适配器测试确定性规则、持久化失败、版本冲突、定位歧义、超时和重试。随后运行真实设备上的两项默认任务，最后跨 Agent 验证。仅模拟两个客户端不算实际跨 Agent 验收。

Jev 错判与 App 弹窗通过固定样本/替身先验证控制流程；实机有无相同弹窗分别报告，不能把注入故障当成自然真实场景。

## 性能口径

同设备/版本/参数/起始状态，预热后传统逐步执行与 Journey 各至少 5 次。报告总耗时中位数与范围、完成次数、Agent/Jev 调用次数、UI 树/截图次数、恢复代价。失败样本保留；若无法同条件对比，明确限制，不报加速倍数。

成功标准：熟路无中途 Agent 思考，重复运行结果正确，并观察到总耗时下降；无提升则继续定位瓶颈，不降低验证要求。少量样本只证明本次试验，不等于生产可靠率。

**收益来源必须是更少的观测与等待，不是进程合并。** 2026-10-20 实测：Phone Harness 单次进程启动仅 0.052s，而一次树读取 2.2–2.4s、一次有界等待 2–5s。因此"一次调用"本身不构成加速；若熟路脚本照搬逐步探索的观察次数，结果会更慢。D 门槛报告必须把观测次数与等待次数单列。

首次学习/验证总成本、端到端时间（含 preparation）和纯执行时间分别报告。跨 Agent 必须实际使用不同客户端/运行引擎的独立会话，不要求不同模型供应商；仅换 prompt 或开两个相同测试进程不满足 R3。Jev 真实视觉单独标明通过/未验证，不影响纯结构任务验收结论的诚实范围。

## 验收口径补充（2026-10-22 修正）

**晋级规则（保持现有 runner.py 实现）**：
- 连续 3 次 completed（`PROMOTION_SUCCESSES=3`）
- 参数化任务覆盖 ≥2 组不同参数（`PROMOTION_PARAM_SETS=2`）
- 环境隔离：按 environment_key 维度独立判定

**完成率记录**：
- 报告实际完成数 / 尝试数，分别列出逻辑失败、环境阻塞和 Agent 介入；不剔除失败美化结果
- 先前提出的 N=10、成功 ≥8 是未经实测支持的工程目标，不是用户指定的验收门槛；撤回其“已确认”表述
- 性能对照样本量与通过条件仍以本文件 D 门槛为准，不替代晋级规则

**Agent 介入续完**：
- 不计入无干预重放晋级（符合 experience-rules §0.4）
- 单独记录"需人工接管率"作为监控指标

**失败清零规则**：
- 逻辑失败（locator_missing / assertion_failed / unexpected_page）：清零连续计数
- 环境阻塞（disconnected / device_busy / 普通唤醒＋上滑后仍 locked 或凭据界面）：不清零，记录环境失败；普通锁屏先尝试受记录唤醒＋上滑，不能直接当作需人工解锁
- 运行前阻塞与运行中失败都需覆盖；取消和环境阻塞不得因写入 validation 就被当成逻辑失败。实现与验证结果分别记录在源码和实验中。

晋级次数/超时默认值见 experience-rules.md；实测修订需记录，不默默改变。

## 已确认的计划验收门槛（2026-10-20）

以下定义源于 Android-first 规划，后续授权见 decisions/，不由此处的历史规划阶段推断当前未获开发授权。Web/Kimi Browser 后置；候选 Journey 仅供参考或显式 validate，只有当前兼容环境经过规则验证的 verified 版本允许普通 run。验收状态与证据分别在 .planning/ 和 experiments/，此处不维护动态结论。

| 门槛 | 关联风险 | 最低验收证据 |
|---|---|---|
| A：Adapter + 自动记录 | U1/U2/U7；R2/R12/R13/R16 | Phone Harness 能力/缺口清单；fake 与真机分别留证；写前持久化（fsync）、原子写入无半写、取消/崩溃后未知结果不重放、不同进程与不同 cwd 共享目录、敏感输入脱敏 |
| B：Journey 安全重放 | U3/U5/U6；R4/R5/R7/R8/R11/R14 | J1/J2 的参数化执行、候选拒绝普通 run、连续 3 次/2 组参数的规则验证、真实 outputs/冻结后置条件；错误页面和版本变化不误报 completed |
| C：跨 Agent 接手 | U4；R1/R3/R15 | 不同真实 Agent 引擎与独立会话，同一存储；Agent B 在不读取 A 聊天的条件下发现并运行 A 学到的 verified Journey；仅模拟客户端不算通过 |
| D：端到端性能 | U4/U5；R6 | 逐步执行与重放在同设备/参数/起点各至少 5 次，记录成功数、中位数、范围、模型及视觉调用、观察次数、学习/验证成本；没有下降则收益未验证 |
| 后续：视觉与网页 | U8/U9；R9/R18 | Jev 真实视觉和 Web Adapter 分别在后续验收；fake 只能证明接口控制路径，不视为服务实际质量 |

门槛 A–D 的通过与否须分别报告：设计审查、模拟测试、真机测试、真实跨 Agent 测试、性能实验不互相替代。任何缺失证据记为未验证或 blocked，而不是通过。风险细节见 open-questions，执行顺序见 implementation-plan。
