# 0004：通用底座 + 薄任务脚本

状态：设计接受。来源：用户询问如何下次快速写出专用流程，并对本方案回复“好的”。本记录不表示重构已实现，也不扩大外部操作权限。

## 决策

通用的是制作、执行和验证专用流程的机制，不要求每个业务流程通用。允许少量专用 Python；不先建设复杂配方语言或任意代码加载平台。

- 公共底座：设备占用、会话、动作与观察留痕、观察复用与失效、预算、计时、失败交还、确定性检查和可选 Jev 接口。
- 任务脚本：输入、App 与页面特征、目标定位、导航步骤、结果提取、成功条件及业务特有失败出口。
- 安全限制由公共调用入口执行；不能仅靠脚本声明只读。专用 Python 是经审查的项目代码，不作为可从不可信 Journey 数据执行的代码。
- 写法：查已有能力 → 基于真实页面探索留证 → Agent 填写薄脚本 → 关键验证与真实回读 → 登记适用条件和证据供下次发现。日志不是自动可靠生成脚本的证明。
- 专用步骤实际重复后再提取共享组件，不预建用不到的抽象。不复制设备锁、计时和失败处理到每个脚本。

## 首个实施切片

用户随后明确要求继续，并指定抖音评论区 AI 总结为第二个更复杂的任务。该范围包括本项目的公共执行层抽取、两个业务脚本及关键测试、真实手机导航和结果读取；不包括公开评论/私信/点赞、主动发送 Chatbot 问题、付费操作或定时任务。抖音脚本可声明已验证的入口前置条件，不得假称支持任意播放页。

以现有 read-post 为样本抽离公共机制，保留小红书知识；再用不同的、授权范围内的真实只读任务验证模板。优先复用现有 session/adapter/runner 能力，不新增另一套并列执行框架。具体接口由源码约束决定，不在本决策中虚构 API。

## 验收

用户进一步接受「给视频链接 → 打开对应视频 → 读取 AI 总结，再换视频验证」作为下一切片目标。沿用本项目代码开发、只读导航和实机验证边界；不将“好的”解释为发送聊天、公开分享或发布授权。候选是否达到目标，以真实入口、视频身份和正文回读核证，不由链接成功启动 App 推出。

- 原有 read-post 仍返回正确结果，使用相同业务后置条件核验。
- 第二个任务只增加任务脚本及登记信息，不修改核心执行器、不复制公共执行机制。
- 换参数确实改变执行目标；参数摘要不同不算绑定成功。
- 目标歧义不乱点，失败不假报成功，外部写入不越权；保留真实证据与整轮计时。
- 可发现、可复用的脚本不自动获得 verified Journey 资格；A–D 仍按 requirements.md 分别核证。
