# 0010：本项目先完成可追溯改进闭环，再推广全局 skill

日期：2026-10-23。状态：用户接受方向后，由主 Agent 在既有授权内细化工程计划；实现与验收状态只在 .planning/。

## 用户意图

用户要求记录实际做过的事，保存关键经验，结论必须有 strong reference；以后 Agent 能依据记录主动找出优化点，不依赖用户逐次手工指出。用户随后明确先完成 Journey Pilot，再推广到每个项目；要求梳理全部关键剩余项、依赖、并行执行和最后的小更新。

## 决策

1. 采用现有文件化计划作为唯一进度来源。L2 的任务与依赖在 docs/implementation-plan.md；L3 继续用当前 .planning 下的 task_plan/findings/progress，不新增竞争计划。参考 Superpowers 的独立任务、反例先行和复核方法，不套用默认重复计划目录、每任务提交或逐包询问。
2. 当前事件日志就是 Trace 的事实基础，复用 run_id、seq、step_id、observation_id、recipe_digest；程序补齐可靠引用和计量，不让 skill 事后凭记忆生成执行事实。
3. 分离执行事实、运行复盘和可复用经验。每条事实结论引用可验证的事件/证据；假设明确标注、附反证条件。经验不直接给予 Journey 执行资格；重放仍走现有 candidate/validate/verified。
4. 先明确持久化白名单与结果缓存语义，再扩展日志。公开结构元数据可长期保存，运行输入/输出/页面内容不因用于复盘而默认持久化。截图、失败详情、locator、摘要和请求缓存一起检查；旧原始证据不静默删除。
5. 项目 skill 负责任务结束/失败后的六问复盘和小改动验证，不宣称 skill 文件本身能自动触发。先在本项目入口与现有 skill 接入；全局安装、各客户端 hook 与自动触发验证在项目收口后单独实施，不在本轮修改用户全局配置。
6. 并行按互不冲突的交付物划分，主 Agent 独占 runner/session/adapter/store/CLI 集成及手机。离线测试、复盘模块、文档/发布检查可并行；共享契约先冻结，禁止多个写入者同时改共同执行路径。
7. 收口包含受限显式故障对账：无动作的遗留占用可在锁/租约条件核实后恢复；已派发未知效果需关联原run/step、新观察和明确效果判断，确认执行进程结束后才允许释放。它不抹掉原未知记录、不重放旧动作、不授予verified；不能靠TTL、单个ack布尔值或看到终态自动解除。无法证明时保持阻塞。通用自动未知解除仍后置。
8. 首版完成标准是本机同用户、Android 只读任务可可靠复用、可追溯改进、可安装验证。固定坐标继续严格受限；无法证明布局适用性时拒绝或回到语义定位，不以完成计划为由放宽检查。公开发布是独立权限 gate，不与本地产品完成混为一项。

## 本轮测试授权补充

2026-10-23 用户明确允许继续调用连接手机进行设置页面、browsing/read-only 与必要编辑测试，明确禁止任何真实发布（包括小红书发布）。本轮使用普通唤醒与只读导航/读取，不推导交易、删除、输入凭据或公开源码权限。用户希望本机交付后直接继续处理新照片和二手文案；尚未提供的新照片不虚构处理结果。

## 不扩大范围

不新增数据库、常驻采集服务、全局任务平台或自主模型训练；不为了收尾追求所有 App、任意恢复、自动消除验证码、批量操作或通用视觉识别。已授权的可逆工程改动和只读测试继续自主推进；依赖安装、外部服务、业务写、提交/推送、公开发布及项目许可证选择保持既有边界。

## 验收原则

完整闭环至少证明一次：实际任务 → 程序记录 → 可核验复盘 → 有边界经验 → 新独立 Agent 查询 → 按经验执行或提出最小改动 → 对照验证。保留失败和准备成本；无新发现允许记录“无变更”，不为了满足模板虚构优化。
