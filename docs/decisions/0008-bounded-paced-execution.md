# 0008：固定段执行保持节奏与操作预算

日期：2026-10-23。状态：方向接受，具体参数与实现待验证。

依据：用户明确希望不要高速连续操作，考虑未来开源后的平台影响，要求探索有节奏的操作方式。此前速度优先的目标补充为：减少 Agent 判断和重复观察，同时限制任务操作量与触发频率；不追求最大吞吐。

## 决策

- 固定段候选记录适用条件、动作与检查点。坐标一致不自动代表跨内容、跨设备或跨版本稳定。
- 页面就绪等待与操作间隔分别建模；等待过后检查观察时效，不能用旧坐标强行继续。
- 本机共享冷却、每任务搜索/刷新/翻页预算、任务去重与停止条件作为发布前执行设计要求；不新增自动巡检或扩量运行。
- 不靠随机动作伪装来承诺负载或账号安全。验证码、异常访问、限流提示交回用户，不规避平台限制。
- 无平台流量计量时，只报告可观察的操作数和耗时，不声称服务端负载下降或多人使用不会有影响。
- 开源默认约束不能保证所有安装的总流量，也不能约束被修改的副本。

本次不选择平台允许速率，不改变既有副作用边界，不承诺固定段已经实现。初始试验参数及限制在 experiments/pacing-study-20261023/REPORT.md，不能当生产阈值。实施顺序见 implementation-plan，执行状态仍仅在 .planning。
