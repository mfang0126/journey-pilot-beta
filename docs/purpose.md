# 产品概念：有条件地复用，持续改进

本文件集中维护产品概念与范围，供设计和方向评审按需阅读，不记录实施进度。用户原话、需求推导和未验证假设见 user-needs；日常怎么做见 [experience-rules §0](experience-rules.md#0-日常工作循环)。

让任何具备本地工具调用能力的 Agent 都能高效控制 Android 真机，并共享执行经验。

## 核心体验

目标体验：Agent A 经 Journey Pilot 做任务，工具保存执行事实；Agent 把有证据的过程与适用条件提炼成经验。Agent B 没有 A 的聊天记录，也能判断是否适用；熟路由程序快速执行，变化由当前 Agent 接手，核对现场后尽量从最近可信位置继续，而不是默认从头再来。这是产品目标，不代表整条闭环已经实现。

记录自动留存不等于自动理解所有业务；候选提炼可以由发起 Agent 完成。工具不依赖 Agent 自觉写运行日志，也不把一次成功自动当成熟能力。

## 哪些稳定，哪些应当 flexible

稳定的是目标与边界：正确对象、真实结果、当次授权、证据和不确定性不可省略。可调整的是路径、入口、观察通道、自动化粒度、等待策略和经验适用范围。改方法不等于放宽成功标准。

通用的是制作、运行、交接和改进经验的方法，不是所有业务步骤必须一样。公共底座负责执行机制；薄脚本保留业务判断。只有真实复用需求出现才抽共享能力，不以“永不改核心”限制合理演进，也不因一个新业务就建通用平台。

经验不是录像式的点击序列，而是有条件的判断：**什么目标，在什么环境和入口下，用什么线索采取什么动作，如何知道结果成立，什么时候不能沿用。** 不适用经验仍有参考价值，但不具有自动执行资格。

## 两个相互促进的循环

**任务循环：** 看目标和现场 → 参考适用经验 → 执行确定段或探索未知段 → 核验结果 → 保存事实与适用条件。途中发现变化，回到当前问题，不默认回到任务起点。

**方法循环：** 从真实使用找到浪费/遗漏 → 分清是条件、观察、执行、验证还是交接问题 → 改最小必要部分 → 用相关样本复核 → 保留证据，再更新方法。一次迭代可以改产品，也可以改我们开发和验证产品的方式；不是每轮都要改代码或写新规则。

一次运行未完成，是一个明确的技术结果，不是整个任务永久失败。它可能留下可复用的成功段、不适用条件或下一次应核验的问题；也允许在成本不合算时暂停。不能为了积极表述把 blocked/failed 改成 completed。

## 自动化和 Agent 的分界

程序执行已经理解、条件满足的部分；Jev 从程序给定的安全选项里做屏幕判断（选哪个、下一步做什么、异常怎么处置），带置信度保险丝；Agent 处理 Jev 拒绝或没有现成选项的新情境、选择证据通道、修复有问题的段。普通页面变化不必都升级给用户；权限、凭据、不可逆业务选择或不可获得的输入才需要用户。现场交接不是任意跳步骤，也不是永久持锁等待；恢复前的核验和知识资格仍受行为规范约束。

手写薄脚本、参考经验和 verified Journey 不混为一类。当前能做到哪里，由源码和实测决定，不能由本概念文档推定。接受本轮方向的记录见 [0005](decisions/0005-flexible-learning-loop.md)。

## 首版范围

- 同一台宿主机上的多个 Agent，共用同一用户权限下的持久化存储。
- Android 真机、Phone Harness、统一 CLI 和配套 skill。
- 执行记录、参数化 Journey、验证晋级、查询匹配、重放、暂停恢复和版本管理。
- 规则优先；Jev 可选地提供有限视觉确认；缺少 Jev 不阻塞结构可判定的任务。

## 后续范围

Kimi Web Bridge 网页适配、跨机器经验同步、共享子流程、地图查询及可视化。首版记录可以为这些能力留出版本化接口，不先实现。

## 非目标

替换底层手机工具、控制任意未授权设备、后台监听所有 Agent 操作、自动遍历全 App、自由执行未知路径、自动创建外部业务操作权限。
